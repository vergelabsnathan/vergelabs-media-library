### The 4.4 ↔ 4.5 boundary

**X1 — Half of one layout decision moved to the script; the other half stayed in PHP at load.** 4.5 moved the File share (30/40/0) into `js/vergeml-media-list.js` because a Screen Options tick changes the visible columns without a reload; the sibling rule in the same PHP function — our columns get `width: 9%` only while `count($visible) <= 8` (`core/media-list.php:244-258`, from `get_hidden_columns()` at load, with the same "CSS counts hidden columns too" comment) — still decides at load. A tick across the 8-column line keeps or loses the 9 % until reload while the share follows live. Sources: adversarial 9, edge-case 5; confirmed by reading both. The fixture never crosses 8, so the spec's live-tick block does not see it. → **defer** (E4-2: the 9 % rule behind a body class the script sets in `share()`, with the ≤8/9 boundary in the live-tick block).

**X2 — Nothing re-measures after `swapTable()` or a resize.** The body class survives a folder click's table swap (the stated reason for putting it on the body, `media-list.php:289-290`), but `measure()` runs once in the frame after load and on a Screen Options change (`vergeml-media-list.js:153-182`); `js/vergeml-tree.js swapTable()` calls `armDraggables(); watchLists();` only. The swapped table has the same columns, so the class still fits; a panel-grip resize or window resize can change the ratio. Sources: adversarial 10, edge-case 4. → **defer** (low; one `vgml:list-swapped` event and a resize listener when the file is next touched).

**X3 — The 4.5 guard and the 4.4 outcome are asserted only by hand-run tools.** What a registered suite pins (`modes.spec.mjs` "the rows on the media list", in `pnpm test:ui` and `box-ui.yml`): checkbox < 60 px per set, the press 40 px into row 1 lands on `.column-title`, the body share class per set, File ≥ share, Screen Options opens, the live tick. Sources: verification-gap 3, 4; `deferred-work.md` already carries "drag.mjs is in no suite" from 4.4's review. → **fix now** (E4-3: `test.skip` with a reason instead of the log; E4-4: `drag.mjs` and `reparent.mjs` registered in `verify.mjs` against Playground — they take base/user/pass already).
