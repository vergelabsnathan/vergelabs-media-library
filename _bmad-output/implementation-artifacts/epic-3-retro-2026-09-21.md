### Spec-to-implementation reconciliation

**R1 — The availability answer overstates what the describe pass does (3.1).** The FAQ shipped in `readme.txt` ("Describing is paused … Pictures waiting to be described are described when it is back") and the live docs page (`service/docs/manual/credits.md:44-50`) were written from `docs/decisions-2026-09.md` row 1, whose reading of `core/ai.php` missed two branches: (a) a transport failure — `wp_remote_post` returning `WP_Error('http_request_failed')` (`ai.php:597-598`) or `vergeml_ai_transport` on the parallel path (`:882, :891`) — never starts with `vergeml_ai_service_`, so `$transient` is false at `:1568-1570` and the picture is stubbed as a permanent error on the first miss (`vergeml_index_set` at `:1605`); (b) a status-carrying outage (5xx/429) holds a picture twice and stubs it on the third strike (`:1583-1601`), and stubs are skipped by the `unindexed` backlog (`:1287-1300`) and by the stale scope. So a service that is *unreachable* — not answering 5xx, but down — stubs every picture the pass touches, and an outage longer than about three holds stubs the rest; nothing describes them "when it is back" until a person re-describes. Sources: adversarial 1, edge-case 11, verification-gap 5; confirmed by reading `ai.php` as cited. The behaviour is the one the code's own comment at `:1551-1566` set out to prevent for 429/5xx and did not extend to transport errors. → **fix now** as a story (E3-1) and the FAQ sentence qualified until it ships — Nathan's words (E3-2). *Upstream lesson:* a decision row's "on file" paragraph was written from line references without a suite run; a behaviour claim that becomes customer text needs the suite line that proves it (NFR1 applied to copy).

**R2 — The prefix note is read only when the agent fails (3.2).** 1c's patch #12 added `(N licences end that way)` to `keyNote` for a prefix with no activation on the site (`route.ts:103-106`); `keyNote` is used only in the fallback mail that goes out when `runAgent` reports `agent failed` (`route.ts:122-134`). `createTicket` takes `licenceId` alone (`:113`), so on the normal path the ticket is stored and briefed as a free install and the prefix is gone. Sources: adversarial 2, edge-case 2; confirmed at the cited lines. → **fix now** (E3-3): persist the prefix (or the note) on the ticket and show it on `/admin/tickets`.

**R3 — Prefix + site needs an activation row; the whole key needed none (3.2).** A moved origin, staging (`environment != production` never activates), a network key, a subsite: all resolved under 4.0.0's `findLicenceByKey` and file as free under 4.0.1's `findLicenceByPrefixOnSite`. Sources: edge-case 1 and 15 (claim `medium`); already found by 1c (row 12) and deferred as Nathan's privacy call (a unique-prefix fallback identifies a customer from four characters). → **defer** (already in `deferred-work.md`; the count note of R2 is the interim, once R2 makes it visible).

**R4 — Two disclosure documents still say the ticket carries the key.** `service/docs/manual/privacy.md:83` ("your licence key if one is set" under `/v1/support/ticket`) and `plugin/docs/security-secrets.md:63` (`core/get-help.php | key | /support/ticket`). `readme.txt` External services was updated in the same commit (NFR5 kept); these two were not. Source: verification-gap 6; confirmed by grep. → **fix now** (E3-4): the privacy page sentence is customer text — Nathan's; the secrets sheet row is the session's.

**R5 — The support promise is stated for three audiences on two addresses.** `readme.txt` Support says *licence holders* write to `support@vergelabsmedia.com`; the site's support heading over the same address says *Pro and Agency* (`public/index.html:2032`); `support/desk.ts:8` defaults `SUPPORT_REPLY_TO` to `support@in.vergelabs.nl` while `/admin/tickets` says replies go out from and come back to `support@vergelabsmedia.com`; the readme FAQ "Where do I report a problem?" (`readme.txt:247-249`) still answers "the issue tracker" only; and the inbound mail webhook files every email ticket with `licenceId: null` (`support/inbound/route.ts:142`), so the channel the readme reserves for licence holders is the one where the service does not know they hold one. Sources: adversarial 5, 6, 7; edge-case 9; confirmed by grep. Decision 2 fixed the address on two surfaces; the audience word and the reply-to were not in its row. → **fix now** (E3-5, one decision for Nathan: which plans the one-business-day promise covers; then the heading, the FAQ line and the `SUPPORT_REPLY_TO` default follow) and (E3-6) inbound tickets resolve the sender's address to a licence when exactly one matches.

**R6 — The two sides of the prefix contract encode it differently.** The plugin sends exactly four upper-case characters (`get-help.php:225-227`); the service accepts `/^[A-Z0-9]{2,8}$/` and never upper-cases (`route.ts:97`); a 2–8-character value costs a query and yields the count note instead of "a shape we do not issue". The plugin is the only sender today. Sources: adversarial 3, 14. → **accept** (recorded; tighten to `{4}` when the route is next touched).
