## 5.5 · Files, paths and uploads — Opus

- **Files:** the 14 sites above (read); `core/import-csv.php` (the upload
  that reads a file), `core/rename-file.php` (assert gated); create
  `tests/security/paths.php` (box); `docs/security-surface.md` gains a
  "Files" section written by hand (not generated).
- **Behaviour:** every path that reaches a delete or a write is resolved
  (`realpath` or `wp_normalize_path` + a prefix check against
  `wp_get_upload_dir()['basedir']`) **before** it is acted on, and a path
  outside uploads is refused. The CSV import reads only the uploaded
  temporary file it was handed and never a path from the request. The
  renamer stays off: `defined( 'VERGEML_FILE_RENAME' )` false on the box,
  and the route it registers absent from the surface table when off.
- **Proof:** `tests/security/paths.php`: for each of the 14 sites reachable
  from a request, a traversal (`../../wp-config.php`), an absolute path
  outside uploads, and a symlink inside uploads pointing out — each refused,
  and the target file unchanged (hash before/after). Mutation: strip the
  prefix check at one site on the box copy and its case goes red.
- **Mirror:** `tests/security/roles.php` for the box-side suite shape;
  `docs/security-db-calls.md` for a per-call table with a reason per row.
- **Copy:** refusal messages are the existing `WP_Error` strings; none new.
- **Do not:** enable the renamer to test it; test on Playground (no real
  filesystem semantics for symlinks); delete anything but the suite's own
  fixture files.

## 5.6 · Outbound requests, and SSRF — Opus

- **Files:** the 19 `wp_remote_*` sites (list above); create
  `docs/security-hosts.md` (hand-written: site → host → what decides it);
  create `tests/security/hosts.mjs` (local, greps the tree like
  `db-calls.mjs`).
- **Behaviour:** every outbound host is one of: a constant in the plugin, a
  `define()` a site owner sets in `wp-config.php`, or derived from one of
  those. None comes from a REST parameter, an option a non-admin can write,
  or a post's content. `VERGEML_AI_SERVICE` and `VERGEML_KNOWN_ISSUES_URL`
  are `define()`s — that is an owner's choice and is documented as such.
  `sslverify` is `true` at every site (it is at `search-meaning.php:106`;
  check the other 18).
- **Proof:** `tests/security/hosts.mjs`: every `wp_remote_*` call in the
  tree appears in `docs/security-hosts.md` with a "decided by" that is one
  of the three kinds; any new call site without a row fails the suite;
  `sslverify => false` anywhere fails it. Mutation: add a
  `wp_remote_get( $_GET['u'] )` to a scratch file and the suite goes red.
- **Mirror:** `tools/db-calls.mjs` + `tests/security/db-calls.mjs` (the
  register-and-drift shape).
- **Copy:** none.
- **Do not:** add an allowlist that a filter can extend (a filter is a way
  in); count `raw.githubusercontent.com` as "ours" without saying it is
  GitHub's.
