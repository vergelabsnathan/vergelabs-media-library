## Findings

### 1. The CSV export evaluates as a spreadsheet formula — needs Nathan

`core/import-csv.php`, `vergeml_csv_line()`. Quoting is RFC 4180, which is correct
for a CSV reader and does nothing for a spreadsheet. A folder named
`=HYPERLINK("http://example.test","Click")` contains no comma, quote or newline,
so it is written to the file unquoted, and Excel, Numbers and Sheets all evaluate
a cell beginning `=`, `+`, `-`, `@`, a tab or a carriage return.

It takes somebody who can name a folder (`manage_categories`) and an administrator
who exports and opens the file. The fix is to prefix such a field with a single
quote and teach the importer to strip one leading `'` back off.

**Why it is not fixed here:** it changes the bytes of a file customers receive, and
the export feeds the import — that round trip is the migration story. A data-format
change is Nathan's call, not a security patch to slip in.

### 2. Forty-seven endpoints write to attachments without asking about the file

A hardening finding, not a vulnerability, and the distinction is evidenced rather
than asserted.

`/autofile-act` (`core/auto-file.php:779` → `core/auto-file.php:402`) and
`/quarantine-act` (`core/quarantine.php:449` → `core/quarantine.php:75`) check that
the attachment **exists** and never that the caller may edit it. `/assign` — the
same act of filing a picture, through the tree — refuses per object at
`core/rest-tree.php:636`, which is the shape `plans/four-yesses.md` names as the
mirror. Forty-seven endpoints sit behind a site-wide `manage_categories`.

On stock WordPress this reaches no file the caller could not already reach, because
every built-in role holding `manage_categories` also holds `edit_others_posts`.
That argument is now a row in `tests/security/roles.php` rather than a belief, so a
site with a custom librarian role that breaks it is told on that site.

**The fix, when it happens:** `edit_post` per attachment, collected into a
`$refused` list the way `/assign` does it. It lands inside `auto-file`, `librarian`,
`organize` and `folder-talk`, four features whose suites are **red and
uncharacterised** — so it belongs after Phase 1 task 1.1, not before it.

### 3. Four undefined globals, sixteen call sites — found, not done

`js/eml-admin.js` defines `window.vergemlConfirmDialog`, `vergemlAlertDialog`,
`vergemlFullscreenSpinnerStart` and `vergemlFullscreenSpinnerStop`. Every call site
spells them **without** the `vergeml` prefix — `emlConfirmDialog` and the rest — and
those names are defined nowhere, so each of the sixteen throws a `ReferenceError`.

It fails closed: `event.preventDefault()` runs first and the handler then aborts, so
the action does not happen at all.

| broken | where |
|---|---|
| Complete Cleanup | `js/eml-options.js:15` |
| Apply settings to the network | `js/eml-options.js:52` |
| Restore default MIME types | `js/eml-mimetype-options.js:77` |
| six taxonomy confirmations and alerts | `js/vergeml-taxonomies-options.js:181, 264, 322, 343, 474, 490` |

A correctness defect, not a hole. It belongs with the board in Phase 1.

### 4. Two filters that accept SQL — found, not done

`core/smart-folders.php` interpolates what `vergeml_smart_count_exclude` and
`vergeml_smart_count_branches` return. Neither carries request input and neither is
reachable by a visitor; both of our own implementations (`core/quarantine.php`,
`core/ai-folders.php`) build from `$wpdb` table names and constants with every
value bound through `prepare()`.

It is still an extension point that accepts SQL, and its contract is documented
nowhere a plugin author would read it. Say so in the docblock, and prefer a branch
that passes `args` over one that interpolates.

## What the tools do that a reader should know

Both classifiers reverse the burden of proof: a call or a sink is a **finding**
until something in the code proves otherwise. That is deliberate, and it is why
this session's first runs reported 40 database findings and 36 unescaped outputs,
every one of which was the reader being blunt rather than a defect. Each was fixed
in the reader instead of annotated in the output, because an annotation is exactly
what 5.3 warns about.

The eleven database calls and twenty-five HTML sinks that resist static proof carry
a written reason **keyed to a hash of the thing they describe** — not a line number
and not an excerpt. Edit the query or the expression and the reason expires.

## Two suite bugs the mutation checks caught, worth remembering

Four of the sixteen mutation checks passed when they should have failed, and all
four gaps were in the new suites rather than in the plugin:

1. **A substring key is not a fingerprint.** The database register matched its
   reason to an excerpt, so appending ` AND kind = $kind` to a reviewed query kept
   the review valid. Keys are now a SHA-1 of the whole statement.
2. **A fixed-length slice overruns.** The `vergeml_ids()` cast check read 600
   characters from the function start, which is half again its length, and the
   `absint()` it found belonged to the next function. It reads to the closing brace.
3. **"Is there an escaper anywhere" is not a check.** `vergeml_pg_head()` losing
   `esc_html()` from its title passed, because the `esc_html()` around its lede two
   lines below answered. Each argument is named now.
4. **A name-only function lookup crosses files.** Four `Walker` subclasses define
   `start_el()`, so looking a function up by name alone can return a body from
   another file and prove a variable against assignments that are not there.

Every one of those is the same mistake in a different coat: asserting the presence
of a good thing somewhere nearby, instead of the specific thing in the specific
place. Worth checking for in the next suite written.
