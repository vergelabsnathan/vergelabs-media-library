## Why, in one line

You are putting the plugin on six agencies' client sites. The one thing the
plugin did that an agency would have called a bug was this: while the AI
service was away, a describe run marked their pictures as failed. It no
longer does.

## What changed

- **A picture the service did not answer for is set aside, not marked.** No
  answer at all (either transport, and a host that blocks outbound requests)
  or a temporary status (any 5xx, 408/425/429, 0) → held ten minutes, nothing
  written, offered again — for as long as the service is away. The old rule
  marked on the first miss when unreachable and on the third temporary error.
- **A refusal about the file still marks it** — and a picture that already
  holds a description keeps it: a failed re-describe leaves the caption in
  search, filing and the counts, stamps the row current so the sweep moves
  on, and reports the failure in the run only.
- **The run and the screen say "waiting", not "failed".** Held pictures are
  out of the run's failed count; a background tick that held everything books
  its next pass five seconds past the hold and does not chase it; the screen
  stops and says *"N described · M set aside — the service did not answer.
  Try again in ten minutes."*
- **Every answer in a batch is read.** The old "four in a row" break threw
  away answers already paid for beside four timeouts — the review's finding 1,
  the one that mattered.
