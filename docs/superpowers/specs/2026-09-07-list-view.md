# The list: the tree stops taking the table's width

Written 2026-09-07 from the corrected diagnosis,
`docs/superpowers/specs/2026-09-06-list-view-diagnosis.md`. The mock is the
stop point: nothing below "What changes in the code" is built until Nathan has
looked at it. Mock: `docs/superpowers/mocks/2026-09-07-list-view.html`.

## What the measurements settled

Three things, and the design follows from them rather than from taste.

1. **A row is as tall as the tallest thing still in the flow.** Core hides row
   actions with `position: relative; left: -9999em` — relative, so they keep
   their vertical space. In a 42px column they wrap to 1,153px and set the
   height of every row. One line of CSS is worth 950px a row.
2. **Our columns are not the cause.** Removing all four changes the row by
   nothing. They are still worth removing — see below — but not for this.
3. **The table is starved before anything else happens.** With every column of
   ours gone *and* FileBird's pane gone, a row is still 348px. At 1600px our
   gutter takes 316 and FileBird takes 319 of 1,440; at 1280 the table is left
   with 457px. A tree that permanently takes 316px from a table it does not own
   is not viable in list mode.

## What changes

### 1. In list mode the tree is a drawer, not a gutter

Grid mode keeps the tree beside the tiles: tiles reflow into whatever width is
left and nothing breaks. A table does not reflow, it crushes, so list mode
gets the whole content width and the tree opens over it.

- The list arrives with **no gutter**: `.wrap` has core's own padding and the
  table has the full width of `#wpbody-content`.
- A control in the filter bar, beside the grid/list switch, reads **`Folders`**
  and carries the count of what is filtered — `Folders · Workspace` when a
  folder is showing.
- Pressing it slides the tree in **over** the list, 300px, with the list dimmed
  behind it. Choosing a folder filters the list and closes the drawer, because
  choosing is the whole reason it was opened.
- Escape closes it. It is never open on arrival.
- Grid mode is untouched.

This is the change that fixes the screen. Everything else is hygiene.

### 2. We add no columns to the list by default

Our four — Media Categories, Colour, Used on, Alt text — come off the default
set. What they said moves under the filename inside core's own File cell, one
quiet line, the way WordPress itself puts row actions there:

```
Gothic Cathedral Interior
vgml-fx-real-499.jpg · Architecture · 68 KB
```

Costs no width, reads better, and survives any other plugin's columns. All four
stay available in Screen Options for anyone who wants them as columns; a person
who turns them on gets what they asked for.

### 3. Row actions may not wrap

`.row-actions { white-space: nowrap }`, scoped to the media list screen. Worth
950px a row on its own, and true whatever else is on the screen. It changes no
positioning, so the hover reveal behaves exactly as core intends.

### 4. Our cells may never grow a row

Any column of ours that a person switches on: `white-space: nowrap; overflow:
hidden; text-overflow: ellipsis`, with the full value on the cell's `title`.
A cell of ours is never the reason a row is tall — including when three of our
columns are on at 1280px.

### 5. The rail, and the fold

Gone from list mode with the gutter. In **grid** mode, where the tree stays:

- Folded, it is a rail 44px wide holding one labelled control and **nothing
  else** — no tree content sliced mid-word.
- The control says which pane it folds, because FileBird's own chevron sits
  38px away and neither says today.
- The fold saves the state that is on the screen. It currently saves the
  opposite, so a reload comes back the other way.

## Copy

Every new string. Nothing else on the screen changes wording.

| where | now | after |

| under the filename, no folder | *(nothing)* | `%1$s · %2$s` — file name, size |
| the rail's control, grid mode | *(unlabelled ‹ ›)* | `Folders` / `Hide folders` |

Kept as they are: the column headings, the grid/list switch, and every error
string.

## What changes in the code

Not built. This is the shape the next session implements once the mock is
approved.

- `core/media-list.php` — our four columns come off the default set; the line
  under the filename is added to the title cell.
- `js/vergeml-tree.js` — the drawer in list mode: the control, the overlay, the
  close on choose and on Escape; the rail in grid mode; the fold saves what is
  on screen.
- `css/vergeml-media-list.css` — the drawer, the rail, `.row-actions`, our
  cells.
- `css/vergeml-tree.css` — the gutter goes in list mode.

## Proof

- `tests/ui/modes.spec.mjs`, extended: **no row on the media list is over
  100px**, in grid and in list, with our columns off and with all four on.
  This is the assertion the suite has never had — it walks this screen today
  and passed throughout while rows were 1,960px.
  Mutation check: put `.row-actions` back to wrapping and it goes red.
- `tests/ui/modes.spec.mjs`: in list mode the table's width equals
  `#wpbody-content`'s, so nothing of ours is taking a gutter.
- The drawer: opens on the control, closes on choosing a folder, closes on
  Escape, filters the list to the folder chosen.
- The fold in grid mode: folded, reload, still folded.

## The decision that is Nathan's

**The drawer.** It is the one real change of shape here — in list mode the tree
stops being visible at rest and becomes something you open. The alternative is
keeping the tree beside the list and accepting a horizontally scrolling table,
which the measurements say is the only other way to give the columns their
width. Board 3 of the mock draws both.
