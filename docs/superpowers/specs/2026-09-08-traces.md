# What every picture rests on

Written 2026-09-08 from `docs/superpowers/specs/2026-09-08-traces-diagnosis.md`
and from the white paper this company publishes, `What does this conclusion
rest on` v6.3 EN. The diagnosis is the argument; this is the contract.

**Nothing here changes what the plugin does.** The describe pipeline, the
scheduler, auto-file, the nightly watch, the folder tree, the Move button and
every existing suite behave exactly as they do today. What changes is that the
plugin stops throwing away the reason, stops letting a language model be the
source of a number, and starts recording who approved what. Three additions,
one removal.

## The three gaps, and what closes each

### 1. The reason is kept — Trail

`vergeml_filing_pick()` already returns `term_id`, `score`, `runner_up`,
`runner_score`, `why` and the full `scores` map. Today all of it is discarded.

It is written to the move that acted on it. `vergeml_librarian_moves` gains
four columns:

| column | what it holds |
|---|---|
| `why` | `ok`, `floor`, `margin`, `gated` — the matcher's own word |
| `score` | the winning folder's score, or the nearest one's when it abstained |
| `runner_up` | the term id it beat, or the one it could not beat |
| `runner_score` | that folder's score |

And two that say what the picture was judged on at that moment:
`prompt_hash` and `model_version`, copied from the index row the score was
computed from. So a move points back at the exact description it rests on, and
that description already points at the model and prompt that produced it. That
is the chain the white paper asks for, end to end, with nobody filling anything
in.

Every write is a byproduct of a move that was going to be written anyway. No
new query on the hot path: the values are in hand when the row is inserted.

**Abstentions are recorded too.** A picture the matcher refused to move is the
most interesting row in the table — it is the answer to the negative question —
so a `gated`, `floor` or `margin` outcome is written with `term_id = 0` rather
than dropped. That is the one place this adds rows: one per picture the run
looked at and left alone.

### 2. The model stops being the source of a number — Constraints, Retrieval

The guide's conversation may propose folders. It may not report counts.

Before the model's message is returned to the browser, the plugin runs
`vergeml_filing_pick()` over the draft — the dry run it can already do — and
the numbers the owner reads come from that. The model's own arithmetic is never
shown.

Three consequences, and they are the point:

- A folder in the draft carries the number the matcher gives it, and the word
  it earned: **31 pictures, and 12 the evidence would not place.**
- The draft has one line the model cannot write: **how many pictures the run
  would leave alone, and why.** That is the negative answer, and it is the
  number an owner most needs before pressing Move.
- The prompt gains one rule, and loses the freedom that made the rest
  necessary. `guideRules` in `lib/guide.ts`: the assistant speaks about the
  draft, never about the library; it never says done, placed, routed, or
  nothing is left unfiled; and it gives no number of its own, because the
  screen beside it has the real one.

### 3. Who approved it is recorded — Approval

`vergeml_librarian_batches` gains `user_id` and `approved_at`. The Move that
applies a draft records the person who pressed it and the moment. An undo
records its own actor the same way.

And one number this makes possible, which the white paper asks vendors for
directly: **on what share of drafts does the owner change something before
filing?** A draft filed unchanged every time is box-ticking. That number is
computable from the batches table once the actor and the draft are on the same
row, and it belongs on the Folders screen where the owner can see their own.

## The removal

`js/vergeml-folders.js:599` stops fabricating `{ rules: [], unfiled: 0,
pictures: 0 }` on a failed request. A failure says it failed, through the
`talk.note()` this file already uses, and the scope choice is disabled while
the number is unknown rather than showing a zero nobody computed. Same for
`js/vergeml-gallery-block.js:66`.

## What a person sees

Two surfaces, and both need a mock before any code:

**On the Folders screen, beside the draft.** Each folder with the count the
matcher gives it, and one line for what it will not place. This replaces
numbers the model wrote with numbers the matcher computed; the shape of the
list does not change.

**On a picture, "why is it here".** The white paper's one-minute answer,
applied to a media library: this picture is in Architecture because it scored
0.81 there against 0.44 for the runner-up, on this object class, described by
this model under this prompt on this date, and filed by this person in this
batch. Read from the two tables, no reconstruction.

Neither is drawn yet. **The mock is the stop point** — nothing in "what a
person sees" is built until Nathan has looked at it.

## Copy

No new user-facing strings are settled in this spec. The two surfaces above
need copy, and copy comes with the mock, from the table in it, verbatim. The
one string this spec does fix is the prompt rule, which is not user-facing copy
but governs what the model produces:

> Nothing you describe has happened. Speak about the draft, never about the
> library. Never say done, placed, routed, or that nothing is left unfiled. If
> the owner asks whether the pictures are in folders, the answer is that the
> draft is ready and filing it is what moves them. Give no counts of your own;
> the screen beside you carries the real ones.

## What this does not do

- **It does not change any decision.** The floor stays 0.55, the margin 0.08,
  the gates stay as they are. This records what the matcher already decides.
- **It does not touch the describe pipeline, the scheduler, auto-file or the
  watch.** Their behaviour is unchanged; the moves they cause carry the reason
  as a byproduct.
- **It does not slow the hot path.** Four values already in memory, written on
  a row already being inserted.
- **It spends nothing.** No new model call anywhere in this spec. The dry run
  is arithmetic over vectors the plugin already has.
- **It is not a compliance feature.** ISO 20252 and the AI Act ask for none of
  this. It is here because the argument this company sells in public should be
  true of the product it sells.

## Proof

- A move made by any route — the guide, the rules, auto-file, a drag —
  carries `why`, `score`, `runner_up`, `runner_score`, `prompt_hash` and
  `model_version`, and they match what `vergeml_filing_pick()` returned for
  that picture.
- A run that abstains writes a row per abstention with `term_id = 0` and the
  reason, and the count of those rows equals the number the run reports.
- The negative question can be answered: one query returns every picture whose
  placement the evidence does not support, and it is not empty on the box.
- Every number the Folders screen shows for a draft comes from
  `vergeml_filing_pick()`; grep finds no count in the model's message.
- `guideRules` carries the rule, asserted by name in `lib/guide.test.ts`, with
  an eval case for *"did you put them in folder yes or no?"* whose pass
  condition is that the answer names the draft and not the library.
- A filed batch names the person and the moment.
- A failed `guide/rules` renders as a failure, not as zeros; the scope choice
  is unavailable rather than wrong.
- The suites that exist today stay green, unchanged: `modes.spec`,
  `shell.spec`, `shots.spec`, `folders.spec`, `tests/tree/*`, and
  `node tools/verify.mjs copy journey guide`.

The plan is `plans/traces.md`.
